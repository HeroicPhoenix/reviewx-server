# ReviewX 项目概览

ReviewX 是按用户隔离题库、解析和作答记录的刷题系统。后端仓库为 `reviewx-server`，配套前端为 `/Users/mack/Documents/WorkSpace/WebStormProject/reviewx-front`。当前功能包括登录鉴权、题库维护与导入导出、三种刷题模式、作答统计、用户创建和 API Key 管理。最新交付状态见 [开发进度](开发进度.md)，文件入口见 [源码索引](源码索引.md)。

## 技术与分层

后端使用 Java 8 编译目标、Spring Boot 2.7.18、MyBatis 2.2.2、MySQL、Druid、Log4j2 和 JWT。Controller 接收校验参数、获取登录用户并返回 ApiResponse；Service 处理业务；Mapper XML 查询数据库。新增联动功能通过 DTO 传递业务结果，在 Controller 转为 VO。

前端使用 Vue 3、TypeScript、Pinia、Vue Router、Axios 和 Vite。`src/api/http.ts` 统一处理业务状态及 401，`src/stores/practice.ts` 保存页面内练习状态，退出登录会清理练习状态。列表不批量加载 Base64，当前题目的图片通过独立接口按需加载。

## 数据语义与保护

`QUESTION` 与 `QUESTION_ANALYSIS` 均使用 `(USER_ID, QUESTION_ID)` 复合主键。查询必须同时限定用户与题目，启用题目状态沿用现有值 1。前端筛选参数 `questionType` 实际对应 `QUESTION_CATEGORY`，不要误用表示单选多选的 `QUESTION_TYPE`。

已解析表示解析文本或解析图片任一个非 NULL 且非空字符串；无解析行、或两者均空表示未解析。保持与实际取题相同的 SQL 判定。加入日期使用 `QUESTION_JOIN_DATE` 的日期值，不是创建时间。

`ANSWER_RECORD` 只允许新增与查询；`QUESTION_ANALYSIS` 永远不得删除，只能精确覆盖同一复合主键。ZIP 清空导入只清当前用户 QUESTION，先预检再写入；题目重新出现时可关联原解析。仅解析导出直接读取解析表，可保留和导出孤立解析。具体红线见 [开发规范第 18 节](coding-standards.md)。

## 运行与验证

后端默认端口 58080，数据库参数来自 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DB`、`MYSQL_USERNAME`、`MYSQL_PASSWORD`，JWT 密钥来自 `REVIEWX_JWT_SECRET`。不将真实凭据写入文档。管理员自动创建默认关闭，Druid 管理页面默认关闭。启动会初始化内置角色权限，接入数据库前应确认环境。

后端根目录执行 `mvn test`；前端根目录执行 `npm test`、`npm run build`。前端开发端口 5173，Vite 将 `/api` 代理至本机 58080。运行时前端配置入口为 `public/config.js` 与 `src/config/runtime.ts`。两端 Dockerfile 已存在，本次未执行容器或部署。

## 后续维护边界

联动筛选目前接入顺序刷题。随机和错题仍沿用原枚举接口；若扩展联动，必须把已做、未做或错题范围也纳入相同的候选题集合。

现有代码仍有 Service 直接返回 VO、导入内部使用 IllegalArgumentException、业务状态字符串等历史写法。新增实现遵守规范，本次没有开展与联动无关的全库重构。开发规范中的 datax 包名和 init.sql 是通用模板，本项目以 reviewx 包、现有 ApiResponse 和 docs/ddl.sql 为实际入口。

异步导入导出任务以进程内存和临时文件保存，重启续传不属于已具备能力。大题库联动查询耗时与 MySQL 执行计划需在真实数据规模下单独评估；当前实现每次请求执行四条去重查询，不把全部题目加载到前端。
