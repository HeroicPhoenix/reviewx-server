# ReviewX 开发进度

## 2026 年 10 月 8 日 顺序刷题联动筛选

已完成前后端代码和本地验证，尚未部署或连接真实业务数据库验收。

### 行为

选择已解析或未解析后，分类、年份、来源和加入日期仅展示该范围内存在的值。每个维度进一步受其他三个已选条件约束；自身维度不约束自身候选，便于直接更换选择。例如选 2026 年后分类仅出现 2026 年存在的分类，进一步选言语理解后日期仅出现该组合存在的日期。

切换解析范围或刷题模式会重置四项筛选；清除某项后重新扩展可选范围。页面重新进入或保存解析后刷新选项，失效值会清除并重新查询。加载期间及失败时禁止继续选择或取题，失败支持重试；请求序号避免旧响应覆盖新状态。随机与错题模式保持原有全库枚举。

### 接口与实现

新增 `GET /api/practice/filterOptions`，权限沿用 `practice:question`；用户 ID 仅从登录上下文获取。可选参数为 `questionType`、`questionYear`、`questionSource`、`questionJoinDate`、`analysisScope`。参数长度与格式校验沿用顺序取题接口。

ApiResponse.data 返回 `questionTypes`、`questionYears`、`questionSources`、`questionJoinDates` 四个数组。分类和来源升序，年份和日期降序，过滤 NULL 和空枚举。Service 返回 QuestionFilterOptionsDTO，Controller 转 QuestionFilterOptionsVO；Mapper 使用四条 DISTINCT 查询和共享 `Practice_Filter_Where`，与顺序取题及总数查询共用解析判断、用户隔离和启用状态条件。

前端 `usePracticeFilterOptions.ts` 集中管理联动状态和请求竞争，PracticeView 负责展示。原题库枚举接口保留。没有表结构、数据写入或权限字典变更，因此 `docs/ddl.sql` 无需修改。

- 前端 `npm run build`：TypeScript 检查与 Vite 构建通过。
- 本地 SQL 验证使用隔离内存库和测试用 DATE_FORMAT 适配，不等同于真实 MySQL 的排序规则、性能或浏览器端到端验收。

### 接续工作

发布时先上线后端接口，再更新前端。真实环境验收顺序为：顺序 → 已解析或未解析 → 2026 年 → 言语理解 → 加入日期，随后清除年份、切换解析范围，核对选项与取题结果。若扩展随机或错题联动，应同时加入作答范围条件。

项目概览、源码索引及两端 AGENTS.md 已建立。以后每轮开发继续更新此记录，历史能力以当前源码和测试为准。

## 2026 年 10 月 26 日 公安备案页脚与 Compose 配置

已完成前端页脚扩展及本地验证，未构建或启动 Docker 容器、未部署线上环境。

### 行为与配置

参考本地 `xunji-yian` 的双备案结构及小警徽资源，在现有 `IcpFooter.vue` 中增加公安备案项；沿用 ReviewX 的淡色玻璃背景、12px 灰蓝文字和轻量悬停效果，警徽为 14px。桌面端并排居中，手机和平板按可用宽度换行；登录页及登录后的页面继续共用同一个页脚。

新增前端运行时变量 `PSB_FOOTER_VISIBLE`、`PSB_TEXT`、`PSB_URL`，与现有 `ICP_*` 独立控制。未填写公安备案号或关闭开关时连同警徽隐藏；两项均关闭或留空时不渲染页脚。默认号码为空，未复制参考项目的备案号。点击警徽或文字在新标签页打开配置的公安备案查询链接；无效、非 HTTPS 或带账号密码的公安链接回退至默认查询页，备案文字按纯文本渲染。

Dockerfile 在容器启动时生成配置，补齐公安备案环境变量，并使用固定 printf 格式保留链接中的百分号及文本中的引号、反斜线。`/config.js` 单独设置 `Cache-Control: no-store`，避免配置更新后继续缓存旧值。新增前端 `docker-compose.example.yml` 和 `docs/备案配置.md`，说明将备案变量合并到已有前端服务的方法。首次启用需构建发布新版前端镜像；之后只改备案配置无需重新编译，重新创建前端容器并刷新页面即可，仅 restart 不会应用 Compose 新值。
